## Check an accepted paper order {/* #inspect-a-paper-order-snapshot */}

[Download the paper order lab](/paper-order-lab.zip). You need Node.js 22 or later and an archive extractor. The ZIP contains a script and three synthetic JSON snapshots of one US stock order in paper trading. The script reads the local files offline. It needs no packages, credentials or Alpaca account.

In the folder containing the ZIP, run:

```sh
unzip paper-order-lab.zip
cd paper-order-lab
node inspect.mjs fixtures/accepted.json
```

This example shows the output for an accepted paper order.

```text
Order: 11111111-2222-4333-8444-555555555555
Status: accepted
Filled: 0 of 10 shares
```

`accepted` means the Trading API received the order. Before your app shows any shares as bought, read `filled_qty`. Here, `qty` is `"10"` and `filled_qty` is `"0"`. Your dashboard should show ten shares requested and zero filled.

## Compare the next two snapshots

From the same lab folder, run both files in sequence.

```sh
node inspect.mjs fixtures/partial.json
node inspect.mjs fixtures/canceled.json
```

Check the order ID in both results. The `partially_filled` and `canceled` snapshots each print `Filled: 3 of 10 shares` for that same ID. The later snapshot still includes the three earlier fills. Adding the two totals would count those shares twice.

For this sample, the final dashboard entry is **3 of 10 shares filled, 7 canceled**. For a customer who supplies only a status, [look up the customer’s own filled quantity](/guides/check-an-order#read-the-filled-quantity-after-cancellation).
